Before your session

  1. Confirm this range is running and choose an exercise with the EMP Range Crew.
  2. Get your assigned account and target scope from the crew.
  3. Review the event rules, available time, and how to request help or a reset.
  4. Record what you tried, what changed, and the evidence you observed.

Use only the systems and activities assigned for your session; coordinate changes and resets with the crew.

What you will explore

Follow the connections between industrial processes, robotics middleware, sensors, and drone dispatch. Choose one zone for a focused session or pair with another attendee to compare test activity with observable evidence.

What is simulated

These labs use real protocol stacks with simulated processes and devices. They do not reproduce physical radio propagation, real flight dynamics in the telemetry emulator, or physical actuator behavior. Available features depend on the profile running at the conference.

grfics-01 / VLAN 20

Factory & OT

GRFICSv3, OpenPLC, ScadaLTS HMI, Modbus/TCP, ROS 2 Jazzy, and virtual CAN.

Try with the crew

Compare the process dashboard with PLC state published to ROS 2. Trace how production output queues a delivery-drone dispatch.

Learning goal

Explain where process telemetry crosses into robotics workflows and which trust boundaries need protection.

Lab boundary: The Modbus-to-ROS bridge is read-only. Ask the crew before exercises that change process values or dispatch behavior.

iot-01 / VLAN 30

Smart IoT & Security

Mosquitto MQTT and a CoAP status endpoint representing doors, motion, cameras, alarms, and temperature.

Try with the crew

Observe the sensor topics and compare their values with the CoAP status response. Discuss the effect of anonymous access to the training broker.

Learning goal

Identify how device state is exposed and propose authentication and monitoring improvements.

Lab boundary: OpenThread is optional and is not connected to the default MQTT/CoAP emulator. This is a sensor-state emulator, not physical building hardware.

drone-01 / VLAN 40

Delivery-Drone Telemetry

Synthetic MAVLink 2 telemetry with ROS 2 and a factory-to-drone dispatch workflow.

Try with the crew

Observe heartbeat, position, and flight-event messages during a crew-approved delivery. Correlate dispatch events with the drone service journal.

Learning goal

Distinguish expected telemetry from unexpected command activity and explain the need for command authentication.

Lab boundary: The default drone is a kinematic emulator. Optional PX4 SITL is not wired into its telemetry or dispatch workflow.

dvd-01 / VLAN 50

Damn Vulnerable Drone

ArduPilot SITL, a companion computer, QGroundControl, and a simulator/management console in DVD lite mode.

Try with the crew

With the crew, choose an upstream DVD scenario and identify the flight controller, ground station, companion interface, and available logs.

Learning goal

Map a drone-system trust boundary and describe the evidence needed to evaluate a mitigation.

Lab boundary: This is independent of the delivery-drone emulator. Full Gazebo mode and physical flight are not provided by this configuration.

wifi-emu-01 / VLAN 60

Virtual Wi-Fi

Linux mac80211_hwsim, hostapd, wpa_supplicant, WPA2-PSK, WPA3-SAE, and a monitor interface.

Try with the crew

Compare WPA2 and WPA3 profiles and inspect a crew-approved capture from the local monitor interface.

Learning goal

Explain authentication and protected management frames, and what a packet capture can reveal.

Lab boundary: Virtual radios and the monitor interface live inside the Wi-Fi VM. They do not model physical RF propagation or belong to the separate Kali VM.
